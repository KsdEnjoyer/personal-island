# Публикация Personal Island

Этот чек-лист предназначен для публикации проекта и его форков. Публикация
исходников и выпуск бинарников — отдельные действия. Установка для конечного
пользователя описана в [инструкции для его личного агента](AGENT_SETUP_RU.md);
инфраструктура автора для неё не нужна.

## Перед первым push

1. Прочитай [отчёт](SECURITY_REVIEW.md), [политику безопасности](../SECURITY.md)
   и [уведомления о сторонних компонентах](../THIRD_PARTY_NOTICES.md).
   Лицензия кода MIT уже указана в Cargo workspace и файле LICENSE.
2. Проверь право распространять свои материалы, темы с персонажными ссылками
   и название проекта; MIT не предоставляет права на чужие бренды.
3. Запусти `python scripts/audit-release.py`, тесты из CONTRIBUTING и аудит
   зависимостей. Он проверяет Git-кандидатов, а не только уже добавленные файлы.
4. Проверь staged diff. Базы, логи, записи экрана, виртуальные окружения,
   OAuth/relay-конфиги и ключи не должны попасть в индекс даже принудительно.
5. Если публикуешь существующую Git-историю, проверь её целиком Gitleaks.
   Удаление секрета только из последнего коммита не очищает историю: сначала
   отзови/замени секрет, затем разберись с историей.
6. Создай пустой репозиторий GitHub без автоматически добавляемого README.
   Первую проверку можно сделать в приватном репозитории.
7. Укажи свою Git-идентичность и remote. Пример, не готовый адрес:

   ```powershell
   git config user.name "YOUR_NAME"
   git config user.email "YOUR_GITHUB_NOREPLY_ADDRESS"
   git add .
   git diff --cached --stat
   git commit -m "Prepare Personal Island for open source"
   git remote add origin git@github.com:YOUR_USER/personal-island.git
   git push -u origin main
   ```

8. В настройках GitHub включи private vulnerability reporting, secret scanning /
   push protection и dependency alerts, если они доступны. Настрой защиту main
   с обязательными проверками и review. GitHub Actions запускаются без
   deployment-секретов и с `contents: read`.
9. Дождись CI и прочитай известные предупреждения. Только после этого меняй
   видимость или публикуй анонс. Не загружай личную папку целиком через web upload.

## Бинарные релизы

Собирай установщик в чистом checkout, используя Cargo.lock и package-lock.json.
Проверь приложение на отдельном профиле Windows, приложи LICENSE/NOTICE и
контрольные суммы. Настрой подпись кода отдельно; неподписанный установщик
может вызвать SmartScreen. Скриншоты делай только с вымышленными данными.
Автоматический release/upload/deploy workflow пока не добавлен.

## Обновление уже работающего подключения

Публикация исходников не обновляет запущенные процессы. Для существующего VPS
нужно отдельно установить новые gateway requirements и перезапустить службу
после проверки/резервного копирования приватной конфигурации. Локальный relay
теперь читает внешний `relay.json`; не переноси его в публичный репозиторий.
Схема установки описана в [инструкции](CHATGPT_MCP_RU.md).
