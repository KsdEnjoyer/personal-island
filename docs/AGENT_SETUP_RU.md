# Настройка Personal Island личным агентом

Этот документ предназначен для AI-агента пользователя с доступом к его
локальным файлам и терминалу. Основной сценарий проекта: пользователь
передаёт настройку своему агенту, а агент выполняет сборку, подключение
и проверку на компьютере пользователя. Это не встроенный автоустановщик.

## Где всё работает

| Режим | Где работают компоненты | Что нужно пользователю |
| --- | --- | --- |
| Только островок | Компьютер пользователя, локальная SQLite | Windows 10/11 и зависимости сборки |
| Личный агент через stdio MCP | Тот же компьютер и та же база задач | Совместимый AI-клиент, запускающий локальный процесс |
| Веб-ChatGPT через HTTPS/OAuth | Компьютер пользователя и его собственный VPS | Свой VPS, домен, TLS, секреты и поддержка MCP в клиенте |

Сервер автора, его домен, учётные записи и ключи не используются. Локальному
режиму VPS не нужен. Выбранный AI-клиент может обращаться к своему провайдеру
моделей и передавать ему запрошенные данные задач; это зависит от клиента.
Погода и музыка используют внешние сервисы, перечисленные в README.

## 1. Осмотр окружения

1. Прочитай [AGENTS.md](../AGENTS.md), [README](../README.md) и
   [SECURITY.md](../SECURITY.md). Работай в каталоге клонированного репозитория.
2. Проверь Windows 10/11, Git, Node.js 24 LTS с npm, Rust stable MSVC,
   Visual Studio C++ Build Tools с Windows SDK и WebView2 Runtime.
   Актуальные системные требования сверяй с
   [официальной документацией Tauri](https://v2.tauri.app/start/prerequisites/).
   Desktop поддерживается на Windows; отдельный stdio MCP также собирается
   на Linux/macOS.
3. Учитывай уже выданное пользователем разрешение на установку и настройку.
   Если действительно не хватает доступа или выбора AI-клиента, уточни именно
   это. Не запрашивай пароли и токены в чате, не печатай их в отчётах или логах.
4. Определи часовой пояс пользователя. `Europe/Moscow` в примерах — пример,
   а не обязательное значение для всех установок.

## 2. Сборка приложения

В PowerShell из корня репозитория:

```powershell
npm.cmd --prefix apps/desktop ci
npm.cmd --prefix apps/desktop run check
npm.cmd --prefix apps/desktop run build
cargo test --locked -p task-core
cargo check --locked -p task-mcp
npm.cmd --prefix apps/desktop run tauri -- build
```

Установщик: `target/release/bundle/nsis/`. Для запуска из исходников вместо
сборки установщика есть `npm.cmd --prefix apps/desktop run tauri -- dev`.
При необходимости создай ярлык через `scripts/create-desktop-shortcut.ps1`.
Не публикуй снимки экрана с личными задачами и содержимым буфера.

## 3. Локальный MCP — основной способ подключения

Следуй [LOCAL_MCP_RU.md](LOCAL_MCP_RU.md):

```powershell
cargo build --locked --release -p task-mcp
```

Зарегистрируй абсолютный путь к `target/release/task-mcp.exe` в выбранном
клиенте. Клиент сам запускает stdio-процесс; сетевой порт и OpenAI API-ключ
для этого не требуются. Настраивай существующий конфиг клиента аккуратно,
сохраняя другие MCP-подключения и настройки. Формат зависит от клиента:
JSON-пример нельзя целиком вставлять в TOML.

Desktop и MCP должны использовать одну базу задач. По умолчанию это
`%LOCALAPPDATA%\PersonalIsland\tasks.sqlite3`. Если пользователь выбирает
другое расположение через `PERSONAL_ISLAND_DB`, задай одинаковый абсолютный
путь обоим процессам. Перезапусти процессы после изменения окружения.
Настрой `PERSONAL_ISLAND_TIMEZONE` для MCP под часовой пояс пользователя.

Включи доступный в клиенте контроль изменяющих действий. Не включай запись
истории буфера автоматически: в новой установке она выключена, пользователь
может включить её в интерфейсе, понимая, что будет сохраняться.

## 4. Проверка без изменения личного расписания

1. Проверь запуск приложения и показ/скрытие островка клавишей Ё / `.
2. Через подключённый MCP вызови `get_current_time`, затем `list_tasks`.
   Сверь время, часовой пояс и доступ к нужной базе. В отчёт достаточно
   результата проверки; не копируй туда всё личное расписание.
3. Для проверки записи используй отдельную временную SQLite-базу и
   временную конфигурацию MCP. Не создавай, не завершай и не удаляй
   тестовые дела в рабочей базе пользователя. После проверки верни клиент
   к выбранной рабочей базе и повтори чтение.
4. Для обычного планирования следуй AGENTS.md: сначала получи текущее время,
   используй даты с часовым смещением, проверяй результаты MCP и дубликаты.
   Удаление и завершение задач выполняй только по явному запросу пользователя.

## 5. Необязательное подключение веб-ChatGPT

Этот шаг нужен только пользователю, который хочет удалённое подключение.
Используй [CHATGPT_MCP_RU.md](CHATGPT_MCP_RU.md) и ресурсы этого пользователя:
его VPS, домен, SSH-ключ и новые независимые секреты шлюза. Названия старых
helper-скриптов с `waicore` не требуют конкретного хостера.

Проверь наличие и назначение сервера до развёртывания; не подставляй чужой
адрес и не меняй существующие сайты без соответствующего запроса. Не открывай
локальный MCP или SQLite в интернет напрямую. Публичный доступ должен идти
через HTTPS и OAuth-шлюз, приватный мост — через защищённый канал.

Храни runtime-конфигурацию, пароли, ключи, базы и логи вне Git checkout.
Примеры в `examples/` — шаблоны, они не содержат готовых рабочих секретов.
Агент вводит секреты через локальное защищённое хранилище или ввод;
он не просит присылать их сообщением. Удалённая настройка не должна делать
приложение зависимым от инфраструктуры автора проекта.

## 6. Что сообщить пользователю

Укажи способ запуска и путь к ярлыку/установщику, выбранный AI-клиент,
часовой пояс и расположение локальной базы. Сообщи, какие проверки прошли,
что осталось не настроено и нужен ли сервер в выбранном режиме.
Не заявляй, что подключение или запись работают, без успешного результата
инструментов. Не включай в итог секреты и содержимое личных записей.
